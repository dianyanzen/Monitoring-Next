# Upload Data PDAK — MONALISA

## Pembaruan tampilan dan menu Data PDAK

Halaman upload mengikuti referensi pengguna: satu panel utama, tanggal entry WIB di atas, empat kartu compact dalam grid 2×2, nama file sumber, area drag/drop, ringkasan pilihan, progress kesiapan dan tombol simpan selebar panel. Warna, border, radius, tombol, kontrol, dan shell mengikuti token dark/light MONALISA; status rinci berada dalam bagian yang dapat dibuka agar tampilan awal tetap ringkas.

Konfirmasi simpan menggunakan komponen **NeonModal** yang dipakai menu MONALISA lainnya, bukan dialog bawaan browser. Pilihan filter laporan menggunakan komponen **SelectDark** proyek. Tidak ada perubahan pada desain global atau menu lain.

Menu **Data PDAK** tersedia di `/pdak/data`, ID **375**, khusus **TEAM IT (5)** mengikuti izin yang sudah dipilih pengguna. API GET `/api/pdak/data?dataset=KIA&date=YYYY-MM-DD` memeriksa izin menu data secara terpisah dan memakai koneksi `DB`. Jika `date` tidak diberikan, server memilih tanggal paling baru yang benar-benar tersedia di tabel kategori terpilih. Tanggal manual dipertahankan ketika kategori diubah; bila kategori lain belum memiliki snapshot tanggal itu, tampilkan empty state. Tidak ada fallback otomatis ke tanggal hari ini.

Tampilan laporan memiliki tab empat kategori, dropdown tanggal snapshot tersedia, filter level kota/kecamatan/kelurahan, pencarian kode/nama, ringkasan jumlah wilayah, pilihan kolom ringkas/semua kolom, serta pagination 20 baris. Angka antarlevel tidak dijumlahkan. Nilai data dirender sebagai teks React. `SelectDark` dipakai mengikuti kontrol menu laporan proyek, dengan token tema PDAK untuk konsistensi light/dark.

Seeder CLI dapat dijalankan ulang dengan `node scripts/pdak-seed-menu.cjs 5 --apply --view`; menu upload tetap terpisah ID 374. Kedua menu memakai cache MONALISA selama 300 detik.

Kelima pengujian pembaca snapshot ditambahkan ke suite: tanggal invalid, default tanggal tersimpan terbaru, tanggal lama dengan binds, dataset kosong, dan whitelist tabel. Suite menjadi **38 tests**. ## Database dan menu

Jalankan audit read-only pada koneksi MONALISA:

```powershell
node scripts/pdak-audit.cjs
```

SQL Developer: jalankan `sql/pdak/PDAK_METADATA.sql` dengan F5 untuk meninjau kolom, constraint, identity, dan menu. Kelima tabel utama sudah ada dan sesuai audit; tidak ada migrasi wajib untuk upload snapshot.

`sql/pdak/PDAK_UPLOAD_BATCH.sql` adalah migrasi terpisah dan idempotent. Jika batch sudah ada, skrip hanya memverifikasi kolomnya. Skrip juga menyediakan **PDAK_UPLOAD_ATTEMPT** opsional untuk riwayat percobaan gagal di UI. Tanpa tabel opsional itu, histori committed tetap berfungsi dan audit kegagalan dicatat melalui `Log`. HTTP tidak menjalankan DDL. Migrasi ini belum dijalankan oleh assistant.

Seeder CLI telah dijalankan sesuai pilihan pengguna untuk **TEAM IT (USER_LEVEL 5)** pada 13 Oktober 2026. Menu ID **374** committed dan izin diverifikasi setelah commit. Level lain tidak diberi akses melalui seeder ini. Skrip idempotent SQL `sql/pdak/PDAK_MENU_SEED.sql` tersedia untuk deployment lain; masukkan level petugas yang disetujui. Menu memakai cache 300 detik: refresh halaman setelah cache kedaluwarsa, atau buka `/pdak/upload` langsung setelah login TEAM IT.

Pool DB yang diaudit adalah pemilik tabel, sehingga SELECT/INSERT adalah hak pemilik. Jika pada deployment lain pool memakai user berbeda, DBA harus memberikan hanya SELECT/INSERT ke empat tabel snapshot, batch, dan attempt bila digunakan, serta SELECT master/menu. Implementasi ini sengaja memverifikasi USER_TAB_COLUMNS pemilik; perpindahan ke user grant/synonym perlu perubahan terverifikasi, bukan fallback ke WEBDB.

## Transaksi dan keamanan

Batch marker dan 182 row memakai koneksi yang sama, executeMany `autoCommit:false`, satu commit. Pre-check batch dan rows legacy tidak menggantikan unique harian sebagai kunci konkurensi. Gagal satu baris membatalkan seluruh kategori. Record attempt terpisah tidak memegang slot harian. Unknown commit outcome diperiksa pada koneksi baru menggunakan ID batch dan hash; tidak dilakukan retry insert otomatis.

Tidak ada UPDATE/DELETE pada snapshot lama. Semua nilai memakai binds. Nama tabel/kolom berasal dari whitelist mapping. User berasal dari session tervalidasi dan izin menu server. POST mensyaratkan origin sama dan membatasi request sesungguhnya, termasuk chunked body: 1–4 file, 10 MiB/file, 40 MiB total, 30 detik baca body, timeout Oracle 15 detik/call. Rate limit 12 POST/menit/user berlaku per proses; deployment multi-instance perlu limit pada proxy bersama.

Parser HTML tidak mengeksekusi script dan menolak konten aktif. OOXML memeriksa central directory, batas entry/ukuran, dekompresi aktual terbatas, XML DOCTYPE/entity, macro, external link, dan formula. `.xls` BIFF ditolak dengan petunjuk simpan ulang sebagai `.xlsx`; fixture asli adalah HTML dan didukung. React merender data sebagai teks. File mentah tidak disimpan di public atau filesystem server.

Dependency review: `npm audit --omit=dev` melaporkan 0 advisori pada dependency produksi terpasang. Referensi primer: [parse5](https://github.com/inikulin/parse5), [ExcelJS](https://github.com/exceljs/exceljs), [advisori UUID ExcelJS](https://github.com/exceljs/exceljs/issues/3041). Override UUID yang sudah ada dipertahankan. Hasil audit berlaku pada lockfile saat pengujian.

Tidak ada pengujian commit produksi atau dua browser authenticated sampai izin menu tersedia.

## Rollback operasional

Matikan akses menu PDAK untuk level yang baru diberikan menggunakan pengelolaan izin MONALISA; kemudian revert hanya file fitur PDAK melalui version control setelah perubahan direview. Jangan menghapus tabel batch atau data snapshot untuk rollback kode. Jika migrasi attempt sudah dipasang, tabelnya dapat dibiarkan sebagai audit. Tidak ada push/deploy atau destructive DDL yang dilakukan.
